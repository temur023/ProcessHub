# Анализ инструкции с положением департамента (Nova)

Реализовано 12 октября 2026. Первая автоматическая функция сверки: должностная инструкция ↔ Положение о департаменте из базы знаний Nova. Код построен так, чтобы следующие виды анализа (бизнес-процессы ↔ положение, задачи процесса ↔ роли и инструкции) добавлялись как новые `kind` тех же запусков.

## Как это работает для пользователя

**Документы → департамент → инструкция → «Анализ и расхождения» → «Проанализировать».**

1. Анализ запускается только по **действующей подтверждённой версии** (дата начала, период и основание указаны во вкладке «Версии»). Это защищает от выводов по черновику.
2. Запуск ставится в очередь и выполняется по шагам. Экран показывает этап и прогресс «k из N», запуск можно остановить:
   - **Чтение инструкции** — пункты раздела «Функции» (если его нет — раздела «Обязанности»). Непринятые исправления Word не учитываются: анализируется действующий текст.
   - **Поиск оснований в положении** — по каждой функции и по названию должности запрос `/retrieve` к базе положений.
   - **Сопоставление функций с положением** — модель банка (режим без базы знаний, наш `system_prompt`) по пакетам из 4 функций и найденных пунктов определяет статус: соответствует / частично / противоречит / нет основания.
   - **Функции положения вне инструкции** — найденные для должности пункты, не сопоставленные ни с одной функцией: модель отбирает те, что относятся к участку должности.
   - **Заключение** — краткий вывод, главное и что сделать.
3. **Отчёт:**
   - **сводка:** счётчики, вывод модели, предупреждения;
   - **фильтры:** «Расхождения», «Все функции» и по статусу;
   - **карточка функции:** пояснение, цитаты пунктов положения с отметкой «цитата найдена в тексте пункта», полный текст пункта и рекомендация.
4. **Эксперт** по каждому замечанию: «Подтвердить», «Отклонить» (с основанием) или «Уточнить» (с вопросом). Решения хранятся в истории и не переписываются; в реестре департамента видно «рассмотрено x из y».
5. **Повторный анализ** создаёт новый запуск, прежние остаются в «Истории запусков». Отчёт неизменяем и привязан к точной версии и файлу.

**Закрепление положения.** Nova хранит положения всех департаментов в одной коллекции. В отчёте «Источники в Nova» видно, из каких документов пришли пункты. Главный администратор закрепляет документ кнопкой «Это положение департамента»; следующие анализы учитывают только его пункты.

## Честные ограничения

- **Охват.** Gateway возвращает до 5 пунктов на запрос и не отдаёт положение целиком. Сверка охватывает найденные пункты, поэтому отчёт всегда помечает её как неполную (`regulation.complete = false`). Полная проверка «все функции положения ↔ все инструкции департамента» требует полного текста положения: загрузить его в библиотеку как «Положение о подразделении» или получить согласованный экспорт от ДИИ. Это следующий этап.
- **Выводы модели — предложения.** Решение принимает эксперт. JSON ответа проверяется; при неверном ответе выполняется один повтор, затем функция получает статус «Не определено», а не придуманный результат. Цитаты сверяются с текстом пункта дословно, с учётом регистра, пробелов и вариантов апострофа.
- **Качество банковской модели не измерено.** Имитатор Nova проверяет только интеграцию. Пороги качества задаются на пилоте по контрольному набору инструкций.

## Подключение Nova

Нужны два разрешения:

1. **Служба ИБ** — сетевой доступ с сервера Process Hub к Nova RAG Gateway (`<gateway-host>:11450`). Соединение исходящее; открывать порт у себя не нужно. В заявке указать IP сервера и цель.
2. **ДИИ, ai@sqb.uz** — API-ключ команды с доступом к базе `ops_policies`.

Затем в `.env` сервера:

```
NOVA_BASE_URL=http://<gateway-host>:11450
NOVA_API_KEY=<ключ>
NOVA_COLLECTION=ops_policies
```

```sh
docker compose --profile knowledge up -d --build
docker compose exec knowledge python -m knowledge_service.cli nova-probe
```

Если доступа нет, запуск анализа завершится понятной ошибкой «Нет сетевого доступа к Nova». Ключ получают только `knowledge` и `knowledge-analysis`; обработчик файлов и браузер его не получают. Каждому запросу присваивается `X-Request-ID` вида `ph-<запуск>-<n>`: по нему ДИИ находит запрос в журналах Gateway.

## Технически

- **Таблицы** (миграция `014_analysis_runs.sql`): `analysis_runs` — задание с этапом, прогрессом, арендой обработчика и результатом. Завершённый запуск неизменяем (триггер), активный — один на документ. `analysis_finding_reviews` — только добавление. `departments.nova_regulation_document` — закреплённое положение.
- **Обработчик** `knowledge-analysis` (`python -m knowledge_service.analysis_worker`) выполняет один запуск за раз: у ключа Nova лимит одновременных запросов. Повторы по документации Gateway: при 429 ждать `Retry-After`, при 502 — до двух повторов с паузой 15 с, остальные ошибки не повторяются. Аренда продлевается на каждом шаге; брошенный запуск после трёх попыток завершается ошибкой.
- **Промпты** — `knowledge_service/analysis_prompts.py`. Любое изменение промпта требует новой `METHOD_VERSION`: отчёт хранит версию методики.
- **API** (через прокси Hub): `GET /nova/status`, `GET|POST /documents/{id}/analysis-runs`, `GET /analysis-runs/{id}`, `POST /analysis-runs/{id}/cancel`, `POST /analysis-runs/{id}/reviews`, `PATCH /departments/{id}/nova-binding`, `GET /departments/{id}/analysis-registry`, `GET /library/overview`.
- **Права:**
  - запуск анализа и решения по замечаниям — `comparisons.manage` («Анализ инструкций»);
  - подтверждение версий — `editions.verify`;
  - оба права назначаются ролью доступа в группе «Проверка и анализ»;
  - закрепление положения — только главный администратор.
- **Имитатор Nova** — `knowledge/dev/nova_stub.py`. Реализует документированный контракт на синтетическом положении. Используется в тестах (`tests/test_analysis.py`) и для демонстрации:

  ```sh
  cd knowledge && NOVA_STUB_DELAY=2 .venv/bin/uvicorn dev.nova_stub:app --port 11450
  ```

  Ключ имитатора — `stub-key`, коллекция — `ops_policies`. Его ответы не оценивают банковскую модель.

## Связанные изменения 12 октября

- **Просмотр Word** по умолчанию показывает действующий текст: непринятые исправления отклонены в копии для чтения, заливка маркером снята. Переключатель «Показать исправления» открывает оригинальную разметку. Оригинал не меняется.
- **Даты актуальности** считаются по календарю Ташкента (`KNOWLEDGE_TIME_ZONE`, по умолчанию `Asia/Tashkent`). Раньше с 00:00 до 05:00 версия, действующая «с сегодняшнего дня», считалась ещё не действующей.
- **Разбор разделов** распознаёт русские заголовки: «2. Функции и задачи», «II. Должностные обязанности», заголовки заглавными без номера.
- **Реестр «Анализ инструкций»** департамента (`GET /departments/{id}/analysis-registry`) показывает актуальность версий, результат анализа и решения эксперта. Стартовая страница документов стала сводкой по департаментам.
- **Ручная сверка удалена** (решение владельца продукта): этапы «в работе / отчёт готов / рассмотрено», её API и таблица `comparison_workflows` (миграция 015 удаляет таблицу только пустой; в рабочей базе записей не было). Ранее сохранённые разборы ответов Nova остаются аналитическими документами библиотеки.
