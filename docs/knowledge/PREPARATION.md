# Подготовка документов к сверке

Реализована 8 октября 2026 внутри «Документов департаментов» Process Hub. Работает без Nova. Выделяет читаемый текст и места в оригинале; утверждение, должностная применимость и смысловая сверка остаются отдельными действиями следующего этапа.

## Текущее представление — 9 октября 2026

Просмотр документа показывает реальные страницы PDF и локальную PDF-копию Word с отдельным исходником. Подготовленный текст не является оригиналом. После уточнения владельца проекта навигация по должностям показывает весь файл; отдельное выделение функций в интерфейсе отключено. Прежние jobs, prepared_sources и API подготовки остаются технической основой, не используемой для чтения документа. Актуальный контракт: [ROLE_LIBRARY.md](ROLE_LIBRARY.md).

## Внутренняя подготовка

Загрузка инструкции или новой редакции атомарно сохраняет оригинал и задание. Отдельный worker подготавливает внутренний источник; страницу можно закрыть. Пользователь выбирает редакцию и открывает полный исходный файл, а не подготовленный текст. Прежний интерфейс поиска по техническим абзацам и отдельное выделение функций убраны из активного маршрута. Выбор инструкции/редакции сохраняется в адресе страницы. API позволяет отменить незавершённое задание или повторить неуспешное; это внутренний механизм подготовки для дальнейшей сверки.

## Источник и качество

Оригинал и `prepared_sources` неизменяемы. Источник связан с `version_id`, SHA-256 оригинала и `parser_version=source-v1`. Блок имеет стабильный ID, порядок, вид, текст, подпись и locator. PDF locator содержит настоящую страницу и текстовый блок. DOCX locator — XML-часть, индекс элемента основного тела, абзац/строку таблицы. Страницы DOCX не выдумываются.

Поддержаны обычный и строгий OOXML DOCX. DOCX сохраняет порядок абзацев и строк таблиц, ссылки, переносы, явную нумерацию и поддерживаемые обычные Word-списки. Сложная нумерация, колонтитулы, сноски, исправления, вложенные таблицы, рисунки и встроенные материалы требуют проверки. Сохранённый технический source-v1 читает текущий текст и исключает удалённые части с предупреждением; это прежний внутренний реестр, а не оригинал. Блок функций DOCX теперь читается непосредственно из исходника (functions-docx-v1) и сохраняет добавленный, удалённый и перемещённый текст. Исправления не принимаются и не отклоняются. PDF сохраняет текстовый слой; порядок и таблицы нужно проверять по оригиналу. Графика, аннотации и страницы без текста дают частичный результат.

Для старого DOC функции теперь читаются через временный OOXML-источник локального Word-движка (`functions-doc-v1`). Он сохраняет исправления и исходную нумерацию, привязан к SHA-256 оригинального DOC и явно обозначает производный locator. Байты DOC и прежний `source-v1` не заменяются. Конвертация не принимает и не отклоняет исправления.

`ready` — основной текст подготовлен; `partial` — есть части для проверки; `needs_ocr` — читаемый основной текст не получен. `ready` не означает нормативную полноту или соответствие. OCR пока не подключён; можно добавить текстовый PDF/DOCX как новую редакцию. Лимиты: 300 страниц PDF, 5000 блоков, 2 млн символов. Превышение останавливает подготовку, не публикуя усечённый текст.

## Очередь и безопасность

Job уникальна по редакции/версии парсера. `queued → running → completed/failed/cancelled`. `completed` означает сохранение источника, его качество задаётся отдельным статусом. PostgreSQL `FOR UPDATE SKIP LOCKED`, lease 90 секунд, heartbeat 5 секунд и токен владения защищают от конкурирующих workers и поздних результатов.

Парсер выполняется в дочернем процессе без Nova/Hub/DB-настроек. Тайм-аут 45 секунд; Linux ограничивает память 512 МБ и CPU 35 секунд. Временные ошибки/потерянный lease допускают максимум 3 попытки с задержкой, затем нужен явный повтор. Отмена, новый захват или истечение lease запрещают публикацию старого результата. Перезапуск сохраняет задания в БД.

Права проверяются на каждом чтении/запуске/отмене; мутации сериализованы с изменениями доступа через блокировку департамента. Пользовательские действия имеют аудит. Worker не выдаёт себя за прежнего загрузившего сотрудника. Ошибки не печатают содержимое, ключи и строки подключения.

API через подписанный прокси Hub:

- `GET /instruction-versions/{id}/preparation` — job/source;
- `POST /instruction-versions/{id}/preparation` — идемпотентный запуск/повтор;
- `POST /instruction-versions/{id}/preparation/cancel` — отмена.

## Запуск и Nova

Docker-профиль `knowledge` запускает отдельный `knowledge-worker` без порта и ключей Nova. Health проверяет недавний цикл worker. Migration006 ставит прежние оригиналы в очередь, не меняя файлы и права.

После настройки ключей оператор запускает `nova-probe`. Явная проверка поиска: `nova-check --query-file /path/query.txt`; `--model-check` дополнительно отправляет синтетический запрос модели. Отчёт содержит доступность, количество фрагментов/метаданных и безопасные ID запросов, без текстов документов. Пустой поиск отличается от недоступного. Доступность модели не подтверждает качество банковской сверки. `full_source_verified=false`: нужен согласованный API/экспорт полного положения.

## Границы приёмки

Тесты проверяют порядок/нумерацию/таблицы/locator, сканы, лимиты, связь с редакцией, неизменяемость, атомарную очередь, повтор, конкуренцию, отмену/поздний ответ, восстановление lease, тайм-аут дочернего процесса и отзыв доступа. Браузерные проверки выполняются на синтетических документах в отдельной базе.

Далее на реальных документах операционного департамента: качество разбора; действующие редакции и применимость; точная связь с положением Nova и полный источник; извлечение функций; двусторонняя сверка с цитатами и экспертным рассмотрением. Эти этапы и G0 данным пакетом не закрываются.
