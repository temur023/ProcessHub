# SQB Process Hub — Python FastAPI Backend

Бэкенд-сервис платформы автоматизации бизнес-процессов **АКБ «Узпромстройбанк» (SQB)**.

Обеспечивает сквозную цепочку:
`Draw.io / BPMN XML` ➔ `PIX BPM Реестры и Регламент` ➔ `Infomaximum Processet (BPMN 2.0 + Event Logs)`.

---

## 🚀 Архитектура и стек технологий
* **Python 3.10+ / 3.14**
* **FastAPI** — высокопроизводительный асинхронный REST API фреймворк.
* **Pydantic v2** — строгая валидация и типизация моделей данных.
* **Uvicorn** — ASGI веб-сервер.
* **zlib / ElementTree** — парсинг сжатых deflate-raw схем Draw.io и спецификации OMG BPMN 2.0.

## ⚡ Быстрый запуск

Карты, их история версий и дерево пространств хранятся в **PostgreSQL**, который
поднимается Docker'ом из `docker-compose.yml` в корне проекта (порт `5433` на
`127.0.0.1`). Без базы бэкенд не запускается и говорит, что поднять:

```bash
docker compose up -d db
```

При первом запуске на пустой базе бэкенд сам переносит в неё карты из
`app/data/process_store.json` и дерево из `app/data/catalog.json` (каждая карта
получает версию «перенос»). Файлы при этом не меняются — это резервная копия на
момент переезда; дальше они не обновляются. Другая база — `SQB_DATABASE_URL`
(по умолчанию `postgresql://sqb:sqb@localhost:5433/sqb`), пароль контейнера —
`SQB_DB_PASSWORD`. Резервная копия базы:
`docker compose exec db pg_dump -U sqb sqb > backup.sql`.

### 1. Запуск через bash-скрипт:
```bash
cd backend
chmod +x start.sh
./start.sh
```

### 2. Запуск вручную:
```bash
cd backend
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python3 -m uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

## 🛠 Ключевые эндпоинты

Всё под `/api/v1`, кроме `auth/*`, открыто только с сессией сотрудника (cookie `sqb_session`),
без неё — `401`. Проверка здоровья и документация открыты. У каждой версии карты в истории
есть автор — тот, кто её сохранил.

| Метод | Эндпоинт | Описание |
| :--- | :--- | :--- |
| `POST` | `/api/v1/auth/register` | Регистрация: имя, рабочая почта `@sqb.uz`, пароль не короче 8 символов; сразу входит. Почта занята — `409` |
| `POST` | `/api/v1/auth/login` | Вход по почте и паролю; неверно — `401`. Сессия живёт 30 дней от последнего запроса |
| `POST` | `/api/v1/auth/logout` | Выход: сессия закрывается |
| `GET` | `/api/v1/auth/me` | Кто вошёл |
| `GET` | `/api/v1/profile` | Профиль: кто вошёл, с какого дня на платформе, сколько версий он сохранил (всего и по видам), на скольких картах, когда последняя правка и его последние 20 карт |
| `PATCH` | `/api/v1/profile` | Сменить имя — оно же у всех его версий в истории |
| `POST` | `/api/v1/profile/password` | Сменить пароль (нужен текущий; неверный — `403`). Остальные сессии сотрудника закрываются, эта остаётся |
| `POST` | `/api/v1/import/file` | Загрузка файла `.drawio`, `.bpmn`, `.xml` и создание процесса |
| `POST` | `/api/v1/import/xml` | Парсинг исходного XML диаграммы из тела запроса |
| `GET` | `/api/v1/import/{id}/export/bpmn` | Экспорт в эталонный **BPMN 2.0 XML** для Infomaximum Processet |
| `POST` | `/api/v1/import/{id}/drawio` | Сохранение из встроенного draw.io: рисунок (`xml`) — в ту же карту новой версией («Правка в draw.io»); id, имя, паспорт, реестр и id страниц остаются от карты. `revision` устарел — `409` |
| `GET` | `/api/v1/import/{id}/export/drawio` | Выгрузка карты в **draw.io** (`.drawio`): все страницы, пулы, дорожки, стили, линии, значки времени; данные платформы — свойствами фигур `sqb_*`. Импортируется обратно той же картой |
| `GET` | `/api/v1/import/{id}/export/pmm?layout=auto\|single\|tree` | Экспорт нативного пакета **PIX Процессной студии** (`.pmm`): одной картой или деревом карт |
| `GET` | `/api/v1/import/{id}/export/event-log` | Экспорт **Event Logs CSV** (журнал событий) для Processet |
| `GET` | `/api/v1/import/{id}/export/regulation` | Экспорт таблицы регламента в **Excel CSV** (UTF-8 BOM) |
| `GET` | `/api/v1/import/{id}/export/pix-json` | Экспорт схемы и реестра в формат **PIX BPM JSON** |
| `GET` | `/api/v1/processes/` | Список всех загруженных процессов |
| `POST` | `/api/v1/processes/` | Сохранить карту. `revision` в теле — ревизия копии, которую правили: если на сервере уже другая, ответ `409`, а не перезапись чужих правок |
| `GET` | `/api/v1/processes/{id}/versions` | История версий карты с автором каждой (правки одного сотрудника подряд в течение 10 минут — одна версия) |
| `GET` | `/api/v1/processes/{id}/versions/{n}` | Карта такой, какой была в версии `n` |
| `POST` | `/api/v1/processes/{id}/versions/{n}/restore` | Вернуть карту к версии — новой версией, история не теряется |
| `POST` | `/api/v1/processes/{id}/registry/cases` | Создание новой заявки/кейса в реестре PIX |
| `GET` | `/api/v1/analytics/{id}/mining` | Метрики Process Mining (SLA, петли возвратов, отклонения) |
| `GET` | `/api/v1/analytics/{id}/rpa-candidates` | Рейтинг шагов по потенциалу роботизации в PIX RPA |
| `GET` | `/api/v1/catalog/` | Дерево пространств, подпространств и карт (номера «3.1», уровни, счётчики) и процессы без пространства |
| `POST` | `/api/v1/catalog/items` | Создать пространство, подпространство или карту (с процессом или без) |
| `PATCH` | `/api/v1/catalog/items/{id}` | Переименовать, перенести, отметить звездой, положить процесс в карту |
| `DELETE` | `/api/v1/catalog/items/{id}` | Удалить пустое пространство или карту (процесс карты остаётся на сервере) |
| `POST` | `/api/v1/canvas/layout` | Линии и подписи страницы для холста — тем же расчётом, что и выгрузка `.bpmn` |

Дерево хранится в базе (таблица `catalog_items`). Структуру
пространства из PIX (ответ `tree/dynamic` студии, сохранённый в JSON) переносит команда
`venv\Scripts\python.exe -m app.services.catalog import-pix <дерево.json>`: номера и порядок
те же, что в PIX, повторный перенос обновляет, а не дублирует.

Холст присылает в `canvas/layout` только фигуры, связи и дорожки страницы (`CanvasPage`),
сжатые gzip (`Content-Encoding: gzip`); полная карта тоже принимается. Посчитанная
раскладка хранится по содержимому страницы и версии кода раскладки (`services/canvas_cache.py`):
в памяти и файлами в `app/data/canvas_cache` (`SQB_CANVAS_CACHE` — другая папка), так что
повторное открытие карты и перезапуск бэкенда её не пересчитывают. После сохранения карты
её страницы считаются заранее, в фоне. Ответы больше 1 КБ уходят сжатыми gzip.

## 🧩 Соглашения экспорта в PIX

Карты банка рисуются по Методике (приложение 2-ILOVA), и экспорт обязан
сохранять её словарь целиком, а не только «шаг — стрелка — шаг».

| Фигура на карте draw.io | Модель | BPMN 2.0 | PIX `.pmm` |
| :--- | :--- | :--- | :--- |
| мелкий таймер без связей, «5 min» | ST шага (`slaMinutes`) | `documentation` + граничный таймер-значок | `intermediate_event_catch_timer` 24×24 у грани шага |
| таймер в потоке, «Kutish vaqti 30 min» | `intermediateTimerEvent` | `intermediateCatchEvent` + `timerEventDefinition` | `intermediate_event_catch_timer` |
| `shape=datastore` (IABS, EHA, EDO) | `dataStore` | `dataStoreReference` | `dataStorage` |
| `mxgraph.bpmn.data2` (Dalolatnoma) | `dataObject` | `dataObjectReference` | `dataObject` |
| `shape=note` | `textAnnotation` | `textAnnotation` | `emptyPool` (рамка с текстом) в дорожке, на которой лежит, вне дорожек — на уровне карты; пунктир к шагу сохраняется. Текст без обводки в draw.io (стиль `text`) идёт с `border_color`/`fill_color="transparent"` |
| пунктир к документу / базе | `kind: association` | `dataInputAssociation` / `dataOutputAssociation` внутри шага | `lineStyle="dotted"` + `line` → `arrowLine` |
| пунктир к примечанию | `kind: association` | `bpmn:association` | `lineStyle="dotted"` + `line` → `arrowLine` |

В PIX карта уезжает **только пакетом `.pmm`**. Импорт BPMN студия
перекладывает по-своему (растягивает карту, дублирует фигуры у границ
дорожек, теряет связи «пул ↔ шлюз»), и время шага BPMN не несёт. BPMN
остаётся эталоном для Processet (`…_Processet.bpmn`) и основой холста.

BPMN пишется строго в порядке схемы BPMN 2.0: в `collaboration` сначала
участники, потом потоки сообщений, потом ассоциации; в `definitions` все
процессы стоят перед всеми `BPMNDiagram` (`pix_spec_checker`, правило
`pix_bpmn_child_order`).

Линии карты:

* пунктир `elbowEdgeStyle` («данные ↔ шаг») рисуется алгоритмом самого
  draw.io — перенос `ElbowConnector`/`SideToSide`/`TopToBottom`
  (`edge_routing.drawio_elbow_route`), сверенный с исходником на
  `tests/fixtures/drawio_elbow_cases.json`;
* в `.pmm` алгоритмом draw.io идут все связи `elbowEdgeStyle` и
  `orthogonalEdgeStyle` (99 % связей карт банка): «ортогональные» — переносом
  `OrthConnector`/`SegmentConnector` с концами из `mxGraphView`
  (`services/drawio_orthogonal.py`; на 10 картах банка совпадает с самим
  draw.io у 2974 связей из 2975). Общий поиск пути с обходом фигур остаётся
  прочим связям;
* «шина» — связь без стрелки между двумя шагами, продолжающая чужой переход
  (параллельное согласование, сведённое в «Kelishildimi?»), — разбирается при
  импорте в переходы от обоих шагов в цель шины (`rejoin_merge_buses`);

* draw.io хранит только те изломы, которые аналитик подвинул руками, а сам
  ведёт связь по осям (`edgeStyle=orthogonalEdgeStyle`). Ломаную восстанавливает
  `services/edge_routing.py` — он же используется на холсте, иначе схема в
  bpmn.io выглядит паутиной диагоналей;
* конец связи в draw.io может быть не привязан к фигуре, а задан точкой
  (`mxPoint as="sourcePoint"`). Такой конец притягивается к фигуре под ним
  (порог 30 px, при равном расстоянии выигрывает меньшая фигура);
* если ни один конец не опирается на шаг — это оформительская линия
  (`kind: annotationLine`, разделители этапов). На холсте она рисуется
  приглушённой, в BPMN и `.pmm` не выгружается: такой конструкции там нет.

Тонкости формата `.pmm`, сверенные с выгрузкой самой Процессной студии:

* узлы внутри `horizontalRoad` позиционируются **относительно дорожки**;
* подпись связи — атрибут **`Text`**, а не `label` (`label` студия игнорирует);
* `waypoint` — **полная ломаная**, включая точки на границах узлов; если
  изломов не было, waypoint не пишем и трассировку делает студия;
* `sourcePoint`/`targetPoint` задаются у каждой связи. На каждой грани фигуры
  у PIX три точки крепления (¼, ½, ¾), и ломаную он берёт как есть, только
  если её концы лежат в этих точках (допуск 0,1 px) и все отрезки идут по
  осям — иначе строит свою линию и вклеивает в неё середину нашей. Без
  номера началом считается правая середина фигуры;
* вид связи PIX выводит из тройки «стиль + маркер начала + маркер конца»:
  переход — `solid`/`line`/`arrowclosed`, ассоциация — `dotted`/`line`/`arrowLine`,
  сообщение — `dashed`/`circle`/`arrowEmpty`. Незнакомую тройку он делает
  сплошным переходом, пунктира без наконечника у него нет;
* `pm/configuration.xml` отдаётся эталонным файлом PIX без изменений:
  имена элементов нотаций (`dfd_process`, `c4_person`, `app_component`)
  заданы студией, и самодельный каталог рискует не пройти её валидацию;
* фигуры стоят и имеют размер **как в draw.io**: импорт правит рамки под
  холст (раздвигает шаг под подпись, отодвигает цилиндр), но исходная рамка
  хранится в `drawioGeometry`/`drawioPoints`, и `.pmm` строится по ней.
  Подпись шага печатается кеглем draw.io (`font_size`), подпись связи — его
  же кеглем и с его переносами строк (`&#10;` в `Text`). Порядок наложения в
  PIX — порядок в файле, поэтому цилиндр под шагом остаётся под шагом;
* события и шлюзы тоже остаются в рамке draw.io: студия рисует их в
  объявленном размере (ромб 50 × 50, таймер 40 × 40), а не палитрой 60/48 px,
  и линии к ним берёт как есть;
* студия кладёт дорожки слоями по порядку в файле, детей — на слой своей
  дорожки плюс один, а узлы уровня карты — под все дорожки (там они выходят
  бледными). Поэтому фигура, задевающая дорожки, вкладывается в последнюю из
  них — таймер на черте между дорожками остаётся, где нарисован, и лежит
  поверх обеих; выступающего за край ребёнка студия не двигает;
* сторона подписи шлюза и цилиндра (сверху или снизу) выбирается так, чтобы
  не лечь на фигуры и на чужие подписи, включая подпись таймера сбоку;
* время таймера пишется на карту всегда (у 20 таймеров оно терялось: импорт
  сначала принимал их за конечное событие). Сторону подписи задал аналитик,
  но в draw.io время под часами лежит на уходящей вниз линии и читается за
  счёт белой подложки, а в PIX подложки нет — такая подпись уходит вбок
  (`event_label_sides`), туда, где нет фигур и линий. Сбоку PIX центрирует
  подпись в коробке 100 px (центр в 54 px от круга), поэтому короткое время
  подбивается неразрывными пробелами с дальней стороны (`side_label_text`) и
  стоит в 6–7 px от круга; в поле «Название» эти пробелы видны;
* подпись связи стоит на линии там, где её видит аналитик: точка берётся
  по правилу draw.io (`drawio_label_point` — доля пути, сдвиг поперёк и
  смещение подписи) или по месту отдельной надписи («XA», оторванная
  подпись — `drawioLabelPoint`), и на линии PIX выбирается ближайшая к ней
  точка. Подписи пунктиров к колонке так остаются между колонкой и
  дорожками, а не уезжают на шаги;
* полоса с названием дорожки в PIX — 30 px, в файле её ширины нет. Название
  влезает целиком за счёт кегля (`font_size` у дорожки, `lane_title`): от
  кегля draw.io вниз до 8, пока строки (интервал 0,9 кегля) не лягут в
  полосу. «…» остаётся только у названия, которое не влезает и в 8;
* пунктир к полосе участника («Mijoz») ведётся **прямо в полосу**, без
  конвертов-посредников. У полосы 12 точек крепления, и они раздаются линиям
  слева направо (`plan_pool_links`): три на обращённой к шагам грани и
  «крючки» в боковые, подходы разведены по высоте — линии не сходятся в одну
  точку и не ложатся одна на другую;
* плашка с именем файла ставится, только если своей шапки у карты нет;
* большая или многостраничная карта уходит **деревом карт** (`pmm_tree`,
  `layout=auto` по умолчанию): одна главная карта со свёрнутыми подпроцессами
  (`sub_process_collapsed`), у каждой дочерней `parentProcessId` — id
  раскрывающего её подпроцесса, как в выгрузке самой PIX. Страницу раскрывает
  фигура с плюсом, которая ссылается на неё в draw.io (`link="data:page/id,…"`,
  при битой ссылке — номер шага «5.» ↔ страница «5»); остальные страницы —
  дорожками обзорной главной карты. Страница больше 500 узлов режется поперёк
  хода процесса там, где разрез пересекает меньше всего линий; линия через
  разрез идёт в событие «в часть N» (`intermediate_event_throw_link`) и
  выходит из «из части N» (`…_catch_link`), цилиндр чужой части приходит
  копией. «Авто» выбирает дерево для файла с несколькими страницами и для карты
  больше 1000 узлов, остальные карты уходят как раньше; `layout=single` — все
  страницы на одной карте, одна под другой;
* время шага — свойства `system_process_time` и `vremya_protsessa`, ожидание —
  `vremya_ozhidaniya` (секунды). Панель показывает шаблон там, где он
  привязан к «Задаче» в нотации (на PIX банка — уровни карт 1–6). Шаблон
  студия ищет по `name`, а «Время процесса» зовутся оба, поэтому обычный
  пишется с `name="vremya_protsessa"` — иначе он остаётся пустым. Таймер
  между шагами («960 min») несёт своё время в `system_process_time` — оно
  видно на панели «Системные» на любом уровне.

### Часы со временем шага в выгрузке

Время операции (ST) и ожидания (WT) раньше уезжало только в
`bpmn:documentation`: в Процессной студии карта открывалась без единой цифры.
Теперь каждый шаг с проставленным временем получает **видимый значок**:

* в **BPMN 2.0** — некрывающий граничный таймер
  (`boundaryEvent` + `timerEventDefinition`, `cancelActivity="false"`) с
  подписью вида «45 мин» или «1 ч 30 мин · ожидание 15 мин». Импортёр рисует
  его на границе фигуры — там же, где часы стоят на исходной карте draw.io.
  Поток он не меняет: исходящих переходов у события нет, и ни один
  `sequenceFlow` на него не ссылается;
* в **`.pmm`** — отдельная фигура `boundary_non_interrupting_event_timer`
  под шагом у правого угла, зажатая в границы дорожки. Если это место занято
  (таймер между шагами, цилиндр, чужие часы), часы уходят вбок: на угол,
  правее шага, затем так же влево (`place_duration_badges`).

Прочитать это обратно умеет фронтенд: `app/src/lib/bpmn-import.ts` и
`app/src/lib/pmm-import.ts` возвращают время значка в ST/WT шага, и в окне
«Просмотр BPMN / PMM» сотрудник видит выгруженный файл с теми же часами, что
и на холсте.

Инварианты выгрузки BPMN проверяются в `tests/test_methodology_export.py`:
стартовое событие без входящих переходов, конечное без исходящих, ассоциации
только к артефактам, `flowNodeRef` только на узлы потока, порядок элементов
`laneSet* , flowElement* , artifact*`, значок длительности у каждого шага с
временем и вне потока управления.
